# 架构与数据边界

本文描述 Meeting Copilot `0.2.2` 的已实现本地架构和验收边界。它不是云端托管服务的部署承诺，也不等同于已完成真实会议、真实网络和真实凭据下的性能验收。

> **当前前端范围**：`0.2.2` 已实现“售前商务会议”模板、Meeting Packet 最小数据集、资料范围隔离、候选预检索复用、三步会议准备、答案专注模式、云端复盘待接入前端，以及 ScreenCaptureKit 的显式停止协议。面试模板已从前端隐藏；已有本地面试历史数据不被删除。完整 `MeetingSession` 持久化、复盘后端和真实性能门禁仍未完成，完整目标架构见 [meeting-copilot-v1-tech.md](meeting-copilot-v1-tech.md)。

## 1. 总体架构

```text
┌──────────────────────────────── macOS 本机 ────────────────────────────────┐
│ React / TypeScript Web UI (Tauri WebView)                                  │
│ 会议模板 · 会议配置 · 资料库 · 实时助手 · 深度复盘 · 设置 · 可观测性          │
│          │ Tauri command / event                                           │
│          ▼                                                                  │
│ Rust Core                                                                   │
│ ├─ Keychain / 加密 SQLite / FTS / 向量 / 引用 / 调用审计                    │
│ ├─ 文档解析编排与本地 PDF 文字提取                                          │
│ ├─ Meeting Packet、范围过滤、问题候选预检索缓存和流式回答编排                │
│ └─ ASR WebSocket 与原生音频桥接管理                                        │
│          │ stdout NDJSON                 │ HTTPS / WSS（用户自带 Key）      │
│          ▼                               ▼                                  │
│ Swift 原生桥接                    腾讯云 / 阿里云百炼                      │
│ ├─ ScreenCaptureKit 系统音频       ├─ 腾讯云实时 ASR                        │
│ ├─ AVAudioEngine 本机麦克风        ├─ Embedding / Rerank                    │
│ └─ PdfTextBridge 本地 PDF 文本     └─ OCR / 流式 Qwen Chat                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

前端不直接访问 Keychain、音频帧或云端密钥；这些能力由 Rust Core 管理。原生 Swift 桥接作为随应用打包的资源进程运行，只通过标准输出向 Rust 输出结构化消息。

## 2. 实时音频与转写

### 2.1 两路采集

| 音频源 | 采集组件 | 角色语义 | 前置权限 |
| --- | --- | --- | --- |
| 会议/系统音频 | ScreenCaptureKit `SCStream` | 匿名远端发言片段 | 屏幕录制 |
| 本机麦克风 | `AVAudioEngine` | 本机发言 | 麦克风 |

系统音频的多人混音只能用于远端片段分离，不能保证真实身份识别。本机麦克风独立标为本机发言。系统音频与麦克风不能互相替代；会议软件的输出设备、macOS 路由和权限会影响前者，输入设备和占用情况会影响后者。

### 2.2 麦克风 PCM 链路

```text
macOS 当前硬件输入格式
  → AVAudioEngine input tap（不强制硬件格式）
  → AVAudioConverter
  → 16 kHz / 单声道 / Int16 PCM
  → base64 NDJSON（Swift stdout）
  → Rust 解码和格式校验
  → 每路 160 帧异步缓冲
  → 腾讯实时 ASR WebSocket 二进制帧
```

麦克风 tap 使用 macOS 选择的真实硬件格式，并在回调内转换为 ASR 所需格式。这样可避免某些内置或蓝牙麦克风在强制 tap 格式时不产生回调。Rust 在 ASR 握手期间保留最多 160 帧音频，避免用户点击“开始采集”后立即说话而在建连期间丢失开头。`0.2.2` 继续向前端发送不含 PCM 正文的累计帧数/音频秒数，并在 `AVAudioEngine` 配置变化时提示重启采集。

### 2.3 采集正常释放协议（0.2.2）

Rust 启动 `MeetingCaptureBridge` 时保留其标准输入；停止采集或客户端退出时，会写入 `{"type":"stop"}` 并最多等待 3 秒。Swift 收到命令后先停止 `AVAudioEngine`，再异步调用 `SCStream.stopCapture()`，写出 `bridge-released` 状态后退出。只有桥接未在超时内退出时，Rust 才强制结束子进程；该情形在本地调用审计中记录为失败级别的“音频桥接强制结束兜底”，而不是伪装为正常停止。

Swift 桥接只负责输出音频帧或采集状态；Rust 仅把转写文本事件发送给 WebView，不把原始 PCM 发送到前端。

### 2.4 ASR 会话状态与失败语义

```text
开始采集
  → 验证设置与权限
  → 建立两条腾讯 ASR WebSocket
  → 启动 Swift 系统音频/麦克风采集
  → 收到 PCM 后标记 audio-receiving
  → 转写事件（中间 / 最终）
  → 停止采集，发送 type:end，等待服务端收尾
```

零音频会话不视为成功：如果 WebSocket 正常关闭但 Rust 从未上传 PCM，调用审计将记录失败，错误为“未收到可上传的 16 kHz PCM 音频帧”。这能与 AppId/签名错误、网络错误和服务端 ASR 错误区分开。

## 3. 知识库与回答链路

```text
导入文件
  → 本地类型识别 / PDF 与 Office 文本提取
  → 扫描页或图片按需 OCR
  → 文本切片 + 来源元数据（页码 / 幻灯片 / 工作表）
  → 云端 Embedding
  → 本地加密 SQLite：文档、切片、FTS、向量、索引状态

系统音频疑似问题
  → 读取当前会议配置的 knowledge_scope
  → 查询向量
  → 仅在本次勾选资料内执行 FTS / 向量召回
  → 融合与云端 Rerank
  → 缓存最多 6 段证据并显示“等待用户确认”
  → 用户确认后复用缓存 + 模板 + 会议上下文
  → 云端流式 Chat
  → 中央答案画布 + 可展开引用
```

空的资料范围直接返回“无足够依据”，不会退化为全库检索。检索与生成遵守证据边界：资料未覆盖的客户事实、接口、数据权限或量化效果必须标注为“待确认”，不能伪装为资料事实。证据片段视为只读事实来源，其中的角色改变、越权、泄露或自动行动指令不会执行。

## 4. 本地数据、密钥与保留策略

| 数据类别 | 保存位置 | 默认保留 | 说明 |
| --- | --- | --- | --- |
| 云端 API Key、资料库密钥 | macOS Keychain | 直至用户替换或删除 | 前端和日志不读取明文。 |
| 文件副本、资料库 | 本机加密目录 / SQLCipher SQLite | 用户管理 | 保存文档、切片、向量、来源与索引状态。 |
| 会议配置与版本快照 | 本机 SQLCipher SQLite | 用户管理 | 支持编辑、复制、删除；删除会议联动删除配置快照，不删除知识库原文件。 |
| 当前转写、答案、引用 | 当前客户端内存 | 进程/页面生命周期 | `0.2.1` 尚未完成 `MeetingSession` 持久化；关闭应用后不作为历史记录保留。 |
| 原始 PCM / 录音 | 不保存 | 不适用 | 仅在当前实时传输过程中驻留。 |
| 模型调用审计 | 本机 SQLCipher SQLite | 最近 200 条供界面读取 | 不保存密钥、音频、提示词正文、资料正文或转写正文。 |

删除资料只清除应用维护的加密副本、切片和向量，不修改用户原始路径中的文件。

## 5. 云端数据最小化

| 云端能力 | 发送内容 |
| --- | --- |
| 实时 ASR | 当前会话的 16 kHz PCM 分片。 |
| OCR | 仅需要 OCR 的扫描页或图片。 |
| Embedding | 已切分的文本。 |
| Rerank | 当前问题和候选切片。 |
| Chat | 问题、回答模板、相关会议上下文和最多 6 个重排证据片段。 |

原文件不会上传到云端知识库服务。使用者必须确认自己对会议转写、录音、资料传输至所选云模型服务拥有必要授权。

## 6. 可观测性

侧边栏“可观测性”读取本地 `model_invocations` 记录，覆盖：

- 腾讯云实时语音转写（系统音频 / 本机麦克风）；
- 百炼 OCR、Embedding、Rerank、流式 Chat；
- 本地 `MeetingCaptureBridge` 的“音频桥接释放”和“音频桥接强制结束兜底”。

每条记录包含提供商、模型、操作、状态、开始时间、耗时、本机估算输入/输出用量和紧凑错误摘要。界面支持按状态及模型筛选，并展示成功率、平均耗时和失败调用数。

“本机估算用量”用于诊断，不能作为云厂商账单或计费对账依据。

## 7. 3 秒验收口径

从 final question segment 时间戳开始，到第一个答案文本事件渲染为止，计为“首字时延”。应用记录采集、ASR、检索、重排、LLM 首字和完成时间。

使用至少 50 条已授权的中英混合问题，在目标网络、目标模型和目标资料规模下计算 P50/P95。只有在“问题结束至首个可读答案文字 P95 ≤ 3 秒”达标后，才可将该指标作为正式试用门槛；否则依次优化候选数、上下文长度、模型、重排和网络链路。

## 8. 构建、打包与版本规则

打包需要 Rust stable、完整 Xcode、Node.js 18+。`npm run build` 会构建 Swift 原生桥接和前端；`npm run tauri -- build` 生成 DMG。

版本必须在下列文件中保持一致：

- `package.json`
- `package-lock.json`
- `src-tauri/Cargo.toml`
- `src-tauri/tauri.conf.json`

DMG 命名规则：`Meeting Copilot_<version>_aarch64.dmg`。打包完成后以 `hdiutil verify` 校验镜像完整性。

## 9. 深度复盘前端边界

`0.2.2` 的深度复盘模块只包含前端导航、五个页签、真实空态和本地 Markdown 导出。该模块没有 Review API、报告任务或云端请求，不上传转写、引用或资料。导出的 Markdown 仅包含当前真实存在的会议配置、资料清单和当前内存转写，并明确写入“云端复盘未接入”。
