# Meeting Copilot 界面设计思路与 Figma 草稿规格

> 版本：v0.1
> 适用端：macOS 桌面客户端（Tauri）
> Figma 草稿：[Meeting Copilot · UI Design Draft v0.1](https://www.figma.com/design/HiCXLQJZtObsn16E1OqKDy)
> 依据：`src/App.tsx`、`src/styles.css`、当前 P0 产品边界与已实现的信息架构。

## 1. 设计目标

Meeting Copilot 不是一个替用户发言的工具，而是一个让用户在高压会议中快速确认事实、组织表达、保持会议节奏的桌面辅助界面。

设计目标按优先级排序：

1. **中央答案优先**：会议中用户的视觉焦点始终是可直接表达、可验证、可编辑的回答建议。
2. **低干扰感知**：实时转写、候选问题、网络与模型状态均为辅助信息，不能压过答案主体。
3. **证据可追溯**：有资料依据、待确认、检索不足、生成失败必须显式区分。
4. **会前配置轻量化**：把场景、主题、参会对象、资料与输出偏好收敛为一个 Meeting Packet，而不是拆成大量设置页面。
5. **本地优先与用户控制**：采集、暂停、删除、导出和资料范围，都要以清晰的用户操作和状态反馈呈现。

## 2. 视觉方向

### 2.1 气质

- 深色默认：深海军蓝作为长时间会议的工作底色，降低白底页面的视觉疲劳。
- 科技感但克制：青蓝用于“正在感知 / 有依据 / 可操作”，靛蓝用于唯一主行动，绿色用于成功或已连接。
- macOS 原生感：紧凑但非拥挤的工具栏、清晰的 8pt 间距节奏、低对比边框与 10–14px 圆角。
- 内容而非装饰优先：不使用大面积渐变、夸张玻璃、强动画或多重阴影；动效只用于状态变化和渐进生成。

### 2.2 当前前端色彩映射

| 语义 | 深色值 | 浅色值 | 使用位置 |
|---|---:|---:|---|
| 页面背景 | `#08111F` | `#F3F7FC` | 主工作区背景 |
| 提升背景 | `#0D1828` | `#FFFFFF` | 答案主舞台、内容承载区 |
| 默认面板 | `#101D2E` | `#FFFFFF` | 卡片、侧栏、表格 |
| 柔和表面 | `#132238` | `#F7F9FD` | 输入区、提示区 |
| 主强调 | `#41B8FF` | `#087FDA` | 连接、链接、活动状态 |
| 主行动 | `#6174FF` | `#3E55E8` | 开始采集、确认、生成 |
| 成功 | `#50DDB1` | `#14956F` | 已连接、已索引、可信依据 |
| 风险 | `#FB7380` | `#D74458` | 错误、删除、停止采集 |

### 2.3 字体与密度

- 生产端：`SF Pro Display / SF Pro Text`，中文回退 `PingFang SC`。
- Figma 端：使用可用的 `Inter`；交付给前端时映射回当前 CSS 字体栈，不改变客户端字体策略。
- 标题：32/40；页面标题：20/28；区块标题：14/20；正文：12/19；元信息：10/14。
- 采用 4pt 基础节奏，常用间距为 8、12、16、20、24、32、40。

## 3. 信息架构与导航

左侧固定导航采用“会议类型 + 功能”两层结构。当前前端仅展示售前商务会议；历史面试数据保留在本地，不在界面呈现。

```text
品牌区
└─ 会议类型
   └─ 售前商务会议

功能导航
├─ 实时助手
├─ 知识库
├─ 回答风格
├─ 会议
├─ 深度复盘
├─ 可观测性
└─ 设置与隐私
```

设计原则：工作区只决定上下文与资料范围；功能导航只决定当前任务。两者不得混在同一层级，以减少“我现在在哪个会议、正在做什么”的认知成本。

## 4. 核心界面规格

### 4.1 会前：会议配置（Meeting Packet）

**目标**：在 2–3 分钟内把本次会议所需上下文收束完毕。

布局：左侧为“会议库 / 最近会议”；右侧为编辑器；编辑器采用三步轻量进度条。

| 步骤 | 字段 | 交互与状态 |
|---|---|---|
| 01 场景 | 场景、主题、会议目标、公司/客户与诉求 | 预置售前商务会议的简洁默认示例，避免空表单焦虑。 |
| 02 材料 | 知识库范围、备注 | 资料显示索引状态和可引用范围；只允许勾选真正适用于本次客户和议题的材料。 |
| 03 表达 | 语言、时长、回答结构、额外要求 | 预设结论—价值—方案—待确认，并允许切换为简洁直答。 |

底部固定操作：`保存草稿`（次级）与 `进入实时助手`（主行动）。未完成字段不阻塞保存，但用“建议补充”而不是红色报错。

### 4.2 会中：实时助手（主界面）

这是产品的主战场，采用 **20% / 56% / 24%** 三栏结构。

```text
┌──────────────┬────────────────────────────────────┬──────────────┐
│ 实时语境      │               AI 回答              │ 会议控制       │
│              │  回答标题 + 可信度状态 + 时延      │ 回答风格       │
│ 我 / 远端转写 │  ──────────────────────────────   │ 当前会议       │
│ 候选问题      │  中央大字号可表达答案             │ 候选问题确认   │
│ 音频健康状态  │  依据摘要 / 复制 / 展开引用       │ 手工提问       │
└──────────────┴────────────────────────────────────┴──────────────┘
```

#### 关键交互

1. **开始采集**：先弹出授权与会议转写知情提示；按钮进入红色 `停止采集` 状态。
2. **实时转写**：麦克风固定标识为“本机发言”，系统音频标识为“远端发言人 A/B”；不显示或承诺远端真实姓名。
3. **候选预检索 + 用户确认**：系统识别疑似问题后，在右栏以小卡片展示问题、证据数量与状态；只有用户点击 `确认生成` 才将其写入中央答案。
4. **中央流式答案**：首字前仅显示轻量骨架和“正在整理依据”；流式时显示细竖光标，不使用整屏 loading。
5. **可信度表达**：
   - `已基于资料整理`：至少有可展示的引用。
   - `待确认`：资料不足、客户事实尚未确认或模型仅提出建议。
   - `建议澄清`：问题缺少关键约束时，优先输出可问的澄清问题。
6. **用户可控**：复制、重问、编辑问题、展开依据、暂停/停止采集均为显式操作；不自动发言、发送消息或生成承诺。

### 4.3 知识库：资料、索引与引用

**目标**：让用户能明确判断“这份资料是否已经真正可被回答使用”。

| 区域 | 内容 | 交互要求 |
|---|---|---|
| 顶部工具栏 | 导入资料、筛选、索引健康提示 | 导入后必须立即出现行记录与“解析 / 向量化 / 完成 / 失败”状态。 |
| 文件表格 | 文件、类型、标签、索引状态、分段、更新时间 | 每行支持查看失败原因、重建、删除；删除只删除本地副本和索引，不删除原文件。 |
| 引用预览 | 片段、页码/幻灯片/工作表、命中分数 | 以侧边抽屉呈现，避免用户在表格中丢失位置。 |

禁止用“已上传”代替“可检索”。`索引中`、`失败`、`0 分段` 都必须是不同且可操作的状态。

### 4.4 会后：深度复盘（P0 仅前端）

**目标**：将一次会议可复盘的信息结构先做完整，云端复盘生成能力在首期以待接入状态展现，不假装已经可用。

布局：顶部选择会议、切换页签；中间三栏为 `会议上下文`、`复盘结果`、`证据与数据`。

| 页签 | 信息结构 | P0 状态 |
|---|---|---|
| 会议概要 | 主题、关键结论、未决问题、行动项 | 前端占位 + 本地会议数据映射 |
| 问题分析 | 高频问题、回答覆盖、待补资料、建议追问 | 前端占位，标记“待接入云端复盘” |
| 证据回看 | 回答引用、关键转写片段、资料命中 | 优先复用本地答案与引用记录 |

完成复盘后，P0 仅提供 **Markdown 导出**。导出页必须带“来源范围 / 待确认事项 / 生成时间”，不应将建议表述为会议事实。

### 4.5 可观测性与设置

- **可观测性**：列表 + 详情双栏；记录 ASR、Embedding、Rerank、Chat 的状态、耗时、估算用量、错误码与可操作建议；不记录密钥、提示词正文、资料正文和原始音频。
- **设置与隐私**：模型提供方、API Key 保存反馈、连接测试、授权状态、数据保留与清除入口。密钥字段只显示“已配置”，不回显明文。

## 5. 状态设计

| 场景 | 视觉语言 | 文字示例 | 用户下一步 |
|---|---|---|---|
| 正在采集 | 蓝色呼吸点 + 轻量波形 | 正在捕捉语音 | 继续、暂停、停止 |
| 音频健康 | 绿色点 + 帧/秒摘要 | 麦克风正常接收 | 无需动作 |
| 候选问题 | 青蓝描边卡片 | 发现疑似问题，已预检索 4 条依据 | 确认生成 / 忽略 |
| 检索不足 | 金色提示 | 当前资料不足，建议补充或澄清 | 查看缺口 / 手工提问 |
| 云端故障 | 红色提示 + 错误原因 | 向量服务请求失败（可重试） | 重试 / 检查配置 |
| 已停止 | 中性状态 | 已停止采集，本次不保留原始音频 | 查看记录 / 清除会话 |

## 6. 动效与反馈规范

- 页面切换：180–240ms 淡入 + 4px 上移，避免位移过大。
- 候选问题出现：220ms 从右侧轻入；用户忽略时淡出，不再反复干扰。
- 流式回答：只在正文末尾显示细竖光标；段落按自然断句进入，禁止字符级跳动造成阅读压力。
- 成功反馈：保存、复制、导出使用 1.2 秒轻量 toast；失败反馈固定在相关模块，不使用只出现一次的全局弹窗。
- 尊重“减少动态效果”系统设置：停用呼吸、波形与流光，保留静态状态标记。

## 7. Figma 草稿结构与当前完成状态

Figma Starter 计划同时存在两个限制：最多 3 页、MCP 调用额度有限。因此草稿采用以下压缩结构：

| Figma 页 | 内容 | 当前状态 |
|---|---|---|
| `00 Cover & Handoff` | 产品界面目标、四个核心页面范围、信任边界 | 已完成 |
| `01 Foundations & Components` | 深色语义色、文字层级、间距与圆角、无障碍说明 | 已完成；组件板待补齐 |
| `02 Core Screens` | 会议配置、实时助手、知识库、深度复盘四个桌面 Frame | 待补齐 |

### 已写入 Figma 的基础资产

- 14 个原始色值、14 个语义色值、14 个布局 token；
- 5 个文字样式：Display / Heading / Section / Body / Meta；
- 2 个阴影样式：Soft / Lift；
- 封面与设计交付说明；
- 深色主题的色板、排版、布局和无障碍说明。

### 待继续写入 Figma 的具体对象

1. `MC / Button`：Primary / Secondary 两个变体，`Label` 文本属性。
2. `MC / Navigation item`：Default / Active 两个变体，含图标位、编号、标签和可选计数。
3. `02 Core Screens / Meeting setup`：三步 Meeting Packet 编辑器。
4. `02 Core Screens / Live copilot`：三栏实时助手，中央回答舞台。
5. `02 Core Screens / Knowledge library`：资料表格、索引状态与引用抽屉。
6. `02 Core Screens / Deep review`：三栏复盘信息架构，云端能力显示“待接入”。

## 8. 前端落地清单

### P0

- 保持中央答案区为实时助手视觉主舞台。
- 实现候选预检索卡片的 `确认生成 / 忽略` 明确分支。
- 为索引状态、ASR 连接、模型报错、音频健康补足组件内固定反馈。
- 深度复盘仅落地前端信息架构、会议选择与 Markdown 导出入口；云端分析逻辑不在该迭代承诺范围。
- 所有关键按钮支持 hover、focus-visible、disabled 与 loading 四态。

### P1

- 将 CSS 的深浅色变量迁移为统一语义 token，支持 Figma 与代码变量一一映射。
- 支持缩小后的单列或双列响应式布局；当前客户端最低宽度为 960px，需单独验证窄窗口场景。
- 为“展开依据”“查看失败原因”“连接测试详情”补充侧边抽屉。
- 完成设计验收：键盘焦点、最小点击区 36px、颜色之外的文本状态、减少动态效果。

## 9. 验收标准

1. 用户在 3 秒内能找到当前会议、采集状态和中央答案；
2. 候选问题不经确认不会覆盖当前回答；
3. 每个答案状态可区分“有依据 / 待确认 / 需要澄清 / 失败”；
4. 文件导入后立即可见，且“索引中 / 已可检索 / 失败”有不同呈现和下一步动作；
5. 会后复盘不会把未接入的云端功能包装成已实现能力；
6. 设计稿、现有 CSS token 与前端组件命名可以互相追溯。

## 10. 已知约束与下一步

- Figma Starter 计划不支持同一变量集合的 Light/Dark 双模式；当前草稿以 Dark 作为绑定基准，浅色值仍以现有 CSS 为实现真相。若升级 Professional，应将 `MC / Color` 改为 Light / Dark 两个别名模式，并让 Frame 通过模式自动切换。
- 本次写入在继续创建按钮组件时触发 Figma MCP Starter 调用额度上限。该 Figma 文件、基础 token 和页面结构均已保留；额度恢复或升级后，应按第 7 节顺序继续，避免重建或重复创建。
- Figma 草稿是界面与交互规格，不代表云端复盘、自动化发言或任何未完成后端能力已经上线。
