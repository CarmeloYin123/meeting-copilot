# Meeting Copilot V1 产品研究与设计记录

状态：V1.0 基线已确认  
日期：2026-08-06  
范围：个人用户 macOS 本地优先会议沟通副驾

## 输入与边界

- 当前客户端为 Tauri 2 + React/TypeScript，Rust Core 与 Swift 原生采集桥接；云端使用腾讯云实时 ASR 与阿里云百炼的 OCR、向量、重排、生成接口。
- 现有能力包含两个内部场景类型、资料导入、本地检索、流式回答、模型设置与本机调用可观测性。它不是已完成生产验收的产品。
- 当前 `MeetingRecord` 只覆盖标题、岗位、JD、备注、时间、状态；尚无 Meeting Packet、会话时间线、简历画像、复盘报告和行动项实体。
- 麦克风可作为“本人”音源，系统音频仅能作为“其他参会者混音”；远端多人的真实身份识别不纳入承诺。
- 原始音频默认不保存。转写、建议与引用按现有本地安全存储策略处理；所有云端调用仅发送完成任务所必需的数据。
- 不提供隐蔽录制、规避会议规则、自动发言/发送、自动报价或代替用户作出承诺，也不分析他人人格或情绪。

## 已确认产品基线（2026-08-06）

| 决策项 | 已确认基线 | 设计影响 |
|---|---|---|
| 首期场景与命名 | 首期仅有“面试会议”和“售前商务会议”两类模板；工作区与场景的用户界面统一称为“会议” | 保留内部场景类型用于 Skill 路由，不在 UI 暴露“工作区”分裂概念 |
| 高级会议字段 | 采用此前推荐默认值：P0 仅保留场景/主题/背景、JD、公司或客户名称、备注、简历、会议要求、资料范围；参会者角色、会议目标、禁答边界后置 P1 | P0 表单和数据迁移保持轻量；P1 扩展字段必须不改变既有 Packet 快照 |
| 简历处理 | 不新增“必须加密保存”或“默认脱敏展示”的产品要求；用户人工确认后才能用于回答 | Keychain 和其他会话/密钥保护边界不受影响；简历原件、画像的保留与删除入口必须清楚可控 |
| 云端复盘 | 初期仅开发云端复盘模块的前端界面和状态，不实现云端后端、任务编排或数据上传 | 页面必须明确“待接入”，不得用示例数据伪装为真实复盘结果，也不得请求云端复盘 API |
| 导出 | P0 只支持 Markdown 导出 | PDF/DOCX/第三方推送均为 P1 |
| 提醒触发 | 默认“候选预检索 + 用户确认” | 候选问题可检索但不自动生成对外可说建议；手动输入仍可触发 |
| 会中展示 | P0 使用主客户端中央答案区 | 悬浮窗后置 P1，当前不作为采集或提示的替代交互 |
| 安全与行为边界 | 不自动发言、发送或对外行动；不分析他人人格或情绪 | 生成契约和复盘 UI 只输出证据、待确认、风险、行动建议 |

## 外部参考的取舍

OfferGoose 的公开介绍可启发“实时提醒、简历/JD 上下文、深度复盘、模拟练习、多语言”等产品方向；Meeting Copilot 不复制其品牌、界面或宣传指标。其“95%、1 秒、20 秒”等页面表述不作为本产品性能承诺。参考：<https://blog.offergoose.cn/zh-cn/post85/>、<https://offergoose.cn/lp/csdn2/>。

## 产品关键判断

1. 首期聚焦面试会议与售前商务会议：两类模板都依赖“实时问题 + 用户授权资料 + 可编辑回答”，底座复用率高。
2. 技术会议、普通会议、自定义场景通过后续 Skill 模板扩展，不建立独立采集或检索链路。
3. 真实会议的核心可信度不是“更像人”，而是“有依据、能说明不确定性、用户可控制”。
4. 实时链路应是固定、可测的工作流，不应使用任意 Agent 工具循环。
5. 云端复盘的真实生成能力后置；当前复盘界面只用于验证信息架构、授权提示和用户预期。

## 选型结论

### 实时编排

采用 Rust `MeetingOrchestrator`：类型化状态机、固定工具链和 Tokio 异步任务。原因是它能保留 Keychain 边界、减少 Sidecar 打包复杂度，并把每一题限制为至多一次向量、一次重排和一次生成。

### 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| Rust 受控状态机 | V1 采用 | 低延迟、单用户、已有 Rust 能力可复用、链路可审计 |
| LangGraph | P1 云端复盘候选 | 适合长任务、人机协同、可恢复状态，但会新增 Python/Node Sidecar 与 IPC |
| LangChain | 暂不引入 | 通用模型/工具抽象对当前 Rust 主链收益有限 |
| ReAct | 仅限 P1 会后受控补充检索 | 是推理模式而非运行时；不能进入实时默认路径 |
| CrewAI/AutoGen | 不建议 | 多角色对话路径、时延和成本不可控 |

LangGraph 与 LangChain 的定位参考其官方文档：<https://docs.langchain.com/oss/python/langgraph/overview>、<https://docs.langchain.com/oss/python/langchain/agents>。

## 需要先验证的假设

| 假设 | 验证方法 | 通过条件 |
|---|---|---|
| 双音源真实收帧与 ASR 可用 | 真机说话和系统音频回放，记录帧数、ASR 字符与错误码 | UI 与 Trace 都能验证非零音频、非零 ASR 文本 |
| 3 秒首字目标可达 | 50 条中英/业务问题，在目标网络和选定模型压测 | 问题结束至首个可读建议 P95 ≤ 3 秒 |
| 资料范围隔离有效 | 给两个 Packet 配置互斥材料并检索 | 回答引用不越界 |
| 简历解析可控 | Word、文本 PDF、图片样本解析后人工确认 | 未确认简历画像不进入回答上下文 |
| 复盘前端边界清楚 | 在无后端的环境走查页面 | 页面无云端请求、无伪造报告，明确显示待接入和数据边界 |
